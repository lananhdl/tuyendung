Mục 2.1

Lịch Sử Các Thế Hệ Ngôn Ngữ

Con người đã tiến hóa cách điều khiển máy tính qua 4 thế hệ lớn:

  • 1GL Mã máy (Machine Code): Nhị phân 0 và 1, thao tác trực tiếp trên phần cứng.
  • 2GL Hợp ngữ (Assembly): Dùng các lệnh viết tắt tiếng Anh (MOV, ADD).
  • 3GL Ngôn ngữ thủ tục (C, Pascal): Gom lệnh thành các hàm (Function) xử lý dữ liệu.
  • OOP Hướng đối tượng (Java, C++): Mô phỏng thế giới thực, gắn liền dữ liệu với hành vi.
Sơ Đồ Tiến Hóa Trừu Tượng Hóa

↓ Rời xa máy móc, tiến gần con người ↓
2GL (Hợp ngữ) MOV AX, 1; ADD AX, BX
↓ Chia bài toán thành các hàm ↓
3GL (Thủ tục) tinhLuong(nhanVien);
↓ Đỉnh cao: Đối tượng tự quản lý mình ↓

Mục 2.2

Thủ Tục (POP) vs Hướng Đối Tượng (OOP)

Lập trình thủ tục (C/Pascal):

Trọng tâm là Hàm (Động từ). Dữ liệu bị thả nổi tự do giữa các hàm. Nếu một hàm vô tình sửa sai dữ liệu chung, toàn bộ chương trình sẽ bị lỗi.

Lập trình hướng đối tượng (Java):

Trọng tâm là Đối tượng (Danh từ). Dữ liệu được bảo vệ nghiêm ngặt bên trong. Muốn sửa dữ liệu bắt buộc phải gọi phương thức của đối tượng đó.

Mô hình Thủ tục: Dữ liệu thả nổi
Dữ liệu chung: soDuTaiKhoan
hamA() sửa
hamB() sửa
hamC() sửa
Mô hình OOP: Đóng gói an toàn
Đối tượng: TaiKhoan
🔒 private double soDu;
⚙️ public void rutTien(amount)
Mục 2.3 & 2.4

4 Trụ Cột Nền Tảng Của OOP

  • 1. Trừu tượng hóa (Abstraction): Ẩn giấu các chi tiết vận hành phức tạp, chỉ hiển thị giao diện cần thiết cho người dùng.
  • 2. Đóng gói (Encapsulation): Gom dữ liệu và hàm vào 1 lớp, khóa biến bằng private để bảo vệ tính toàn vẹn.
  • 3. Kế thừa (Inheritance): Lớp con sử dụng lại toàn bộ thuộc tính, phương thức của lớp cha mà không cần viết lại.
  • 4. Đa hình (Polymorphism): Cùng một lời gọi hàm nhưng các đối tượng con khác nhau phản hồi theo cách khác nhau.
Trừu Tượng Hóa Lái ô tô chỉ cần đạp ga/vô-lăng, không cần can thiệp hộp số.
Đóng Gói Két sắt bảo vệ tiền, muốn rút phải qua cửa kiểm tra mã PIN.
Kế Thừa Lớp Nguoi ➔ SinhVien (kế thừa HoTen, NgaySinh).
Đa Hình Lệnh tiengKeu(): Mèo kêu Meo Meo, Chó sủa Gâu Gâu.
Mục 3.1 & 3.2

Lớp (Class) & Đối Tượng (Object)

• Lớp (Class): Bản thiết kế định nghĩa các thuộc tính và phương thức.
• Đối tượng (Object): Hiện thân cụ thể được tạo ra trên bộ nhớ Heap bằng từ khóa new. 

public class Main {
    public static void main(String[] args) {
        // Tạo đối tượng từ Class SinhVien
        SinhVien sv1 = new SinhVien();
        sv1.ten = "Hoàng";
        sv1.hocBai();
    }
}
Bản Vẽ (Class)
SinhVien
- String ten
- double gpa
+ hocBai()
➔ ➔
Đối Tượng Thật (Object)
sv1
ten = "Hoàng"
gpa = 8.5

Từ 1 bản vẽ Class duy nhất, ta có thể khởi tạo hàng ngàn Object độc lập trong bộ nhớ.

Mục 3.3 & 3.9

Bản Chất Đối Tượng & Tham Chiếu

Biến đối tượng trên Stack thực chất chỉ chứa địa chỉ vùng nhớ (tham chiếu), trỏ đến dữ liệu thực sự nằm trên vùng nhớ Heap. 

SinhVien a = new SinhVien("Bình");
SinhVien b = a; // Copy địa chỉ vùng nhớ!

b.ten = "Dũng";
System.out.println(a.ten); // Kết quả: "Dũng"

Vì a và b cùng trỏ chung một địa chỉ ô nhớ trên Heap, sửa qua b thì a cũng đổi!

0xFA12

Mục 3.4

Nạp Chồng (Overloading)

Các phương thức trong cùng 1 lớp có cùng tên nhưng khác nhau về danh sách tham số (khác số lượng hoặc khác kiểu dữ liệu). 

public class MayTinh {
    int cong(int a, int b) { 
        return a + b; 
    }

    int cong(int a, int b, int c) { 
        return a + b + c; 
    }
}
Trình Biên Dịch Tự Điều Hướng (Compiler Dispatch)
Lời gọi: mayTinh.cong(5, 10, 20);
↓ Đối chiếu danh sách tham số ↓
cong(int, int)
❌ Không khớp (thiếu tham số)
cong(int, int, int)
✅ Khớp 3 số nguyên!
Mục 3.5

Hàm Khởi Tạo (Constructor)

  • • Tên phương thức phải trùng 100% với tên Class.
  • • Không có kiểu trả về (kể cả void).
  • • Tự động thực thi ngay lập tức khi đối tượng được sinh ra bằng từ khóa new.
public class Hero {
    String ten;
    int mau;

    public Hero(String t) {
        this.ten = t;
        this.mau = 100; // Mặc định khởi tạo
    }
}
Quy Trình Khởi Sinh Đối Tượng
1. Lệnh gọi: new Hero("Yasuo");
↓ Cấp phát vùng nhớ & Kích hoạt Constructor ↓
Đối tượng hình thành với dữ liệu sẵn sàng
ten: "Yasuo" | mau: 100
Mục 3.6

Interface & Implementation

• Interface (Giao diện chuẩn): Bản hợp đồng quy định hệ thống làm được gì (chỉ có tên phương thức, không có mã thực thi).
• Implementation: Các lớp cụ thể viết mã hiện thực hóa hợp đồng đó. 

interface CongTypeC {
    void napDien();
}

class SacNhanh implements CongTypeC {
    public void napDien() { ... }
}

Mục 3.7

Đóng Gói (Encapsulation)

Che giấu thông tin nhạy cảm bằng từ khóa private. Mọi truy xuất đều phải thông qua các cổng kiểm soát công khai Getter và Setter. 

public class NganHang {
    private double soDu; // Khóa dữ liệu

    public void napTien(double tien) {
        if (tien > 0) this.soDu += tien;
    }
}
Mô Hình Bảo Vệ Két Sắt
🔒 private double soDu;
Bên ngoài không thể gọi tk.soDu = -9999;

Mục 3.8

Kiểu Cơ Bản vs Kiểu Đối Tượng

  • Kiểu cơ bản (Primitive): int, double, boolean, char... Lưu trực tiếp giá trị số trên bộ nhớ Stack, không thể mang giá trị null.
  • Kiểu đối tượng (Reference): String, SinhVien, Array... Lưu địa chỉ trên Stack trỏ sang Heap, có thể chứa null.
Kiểu Cơ Bản
int age = 20;

Giá trị 20 nằm trực tiếp tại ô nhớ của biến trên Stack.

Kiểu Đối Tượng
String s = "Java";

Biến s chỉ chứa địa chỉ, trỏ tới chuỗi "Java" nằm trên Heap.

Mục 3.10

So Sánh: `==` vs `.equals()`

• Toán tử `==`: So sánh 2 địa chỉ vùng nhớ.
• Phương thức `.equals()`: So sánh nội dung ký tự thực tế bên trong. 

String s1 = new String("TEST");
String s2 = new String("TEST");

System.out.println(s1 == s2);      // false ❌ (Khác ô nhớ)
System.out.println(s1.equals(s2)); // true  ✅ (Cùng nội dung)
Minh Họa Vùng Nhớ Heap
Địa chỉ: 0x111
"TEST"
Địa chỉ: 0x222
"TEST"
0x111 == 0x222 là Sai, nhưng nội dung đều là chữ "TEST" nên .equals() trả về Đúng.
Mục 3.11

Truyền Tham Số (Pass-by-Value)

Java chỉ có duy nhất cơ chế Pass-by-Value (truyền bản sao giá trị). Với đối tượng, bản sao được truyền đi chính là bản sao địa chỉ vùng nhớ. 

void tangMau(Player p) { 
    p.hp += 50; 
}

Player hero = new Player(100);
tangMau(hero); 
// hero.hp trở thành 150!
Bản Sao Địa Chỉ Trỏ Cùng Ô Nhớ
hero: 0x9A
➔
Object Player
hp: 100 ➔ 150
⬅
tham số p: 0x9A
Mục 3.12

Từ Khóa `this` Trong Java

Từ khóa this đại diện cho chính đối tượng hiện tại đang thực thi code, giúp phân biệt rõ giữa thuộc tính của lớp và tham số truyền vào khi chúng trùng tên. 

public class SinhVien {
    String hoTen;

    public SinhVien(String hoTen) {
        this.hoTen = hoTen; 
        // this.hoTen: Thuộc tính lớp
        // hoTen: Tham số truyền vào
    }
}
Khử Sự Nhập Nhằng Biến
this.hoTen ➔ Thuộc tính của Object trong Heap
hoTen ➔ Tham số tạm thời trên Stack
Mục 3.13

Thành Viên `static` & `package`

  • Từ khóa `static`: Biến hoặc hàm thuộc về toàn bộ Class, dùng chung cho mọi đối tượng, gọi trực tiếp mà không cần lệnh new.
  • Gói `package`: Cơ chế thư mục phân cấp mã nguồn, ngăn ngừa xung đột tên file giữa các nhóm lập trình.

Mục 3.14

Quan Hệ Thành Phần (Composition)

Quan hệ "Has-A" (Sở hữu) có tính sống còn: Đối tượng lớn được hợp thành từ các đối tượng thành phần nhỏ. Khi đối tượng cha bị hủy, các thành phần con cũng mất theo. 

public class Smartphone {
    private Pin battery; // Has-A

    public Smartphone() {
        this.battery = new Pin();
    }
}
Thực Thể Phức Hợp
📱 Smartphone
🔋 Pin (Battery)
🖥️ Màn Hình
