Mục 9.1

Khái Niệm Luồng Dữ Liệu (Stream)

Trong Java, Stream (Luồng) là một chuỗi tuần tự các byte dữ liệu di chuyển từ Nguồn (Source) tới Đích (Destination).

1. InputStream / Reader (Luồng vào):

Đọc dữ liệu từ bên ngoài (bàn phím, file, mạng internet) vào bộ nhớ RAM của chương trình.

2. OutputStream / Writer (Luồng ra):

Ghi dữ liệu từ chương trình Java xuất ra màn hình, ghi xuống đĩa cứng hoặc truyền đi qua mạng.

Dữ liệu được xử lý tuần tự từng phần nhỏ, không cần nạp toàn bộ dữ liệu khổng lồ vào RAM cùng lúc.

Mục 9.1 Chi Tiết

Luồng Byte vs Luồng Ký Tự

Java chia hệ thống I/O thành 2 nhánh lớn dựa trên đơn vị dữ liệu được vận chuyển:

  • 1. Byte Streams (InputStream / OutputStream): Xử lý dữ liệu nhị phân nguyên thủy từng 8-bit (1 byte). Dùng cho file hình ảnh (PNG, JPG), âm thanh (MP3), video, file nhị phân (PDF, DOCX).
  • 2. Character Streams (Reader / Writer): Xử lý văn bản từng 16-bit Unicode (2 bytes). Tự động hỗ trợ bảng mã UTF-8/Unicode, dùng cho văn bản tiếng Việt có dấu, file TXT, JSON, XML.

Mục 9.2

Cơ Chế Lắp Ráp Luồng (Chaining Streams)

Java I/O áp dụng Decorator Pattern: Lồng luồng này vào trong luồng khác như các khúc ống nước để bổ sung thêm tính năng (như bộ đệm đệm tăng tốc độ, đọc từng dòng chữ, mã hóa). 

// 1. Khúc ống lõi: Nối trực tiếp vào file
FileReader fr = new FileReader("data.txt");

// 2. Bọc ống đệm (Buffer): Tăng tốc độ đọc gấp hàng chục lần
BufferedReader br = new BufferedReader(fr);

// Đọc tiện lợi từng dòng:
String line = br.readLine();
br.close(); // Tự động đóng toàn bộ các ống bên trong
Minh Họa Lồng Ống Nước (Wrapping)
Ống Ngoài Cùng: BufferedReader (Hỗ trợ readLine(), lưu bộ đệm 8KB)
↓ lồng vào trong ↓
Ống Chuyển Đổi: InputStreamReader (Giải mã nhị phân sang UTF-8)
↓ nối thẳng vào ↓
Ống Cơ Bản: FileInputStream (Đọc từng byte thô từ đĩa cứng)
Mục 9.3

Đọc/Ghi File & Tự Động Đóng Luồng

Thao tác file bắt buộc phải đóng luồng (close()) để giải phóng con trỏ đĩa. Dùng cú pháp try-with-resources (từ Java 7+) giúp Java tự động đóng luồng 100% mà không cần viết khối finally phức tạp. 

// Tự động close() khi kết thúc khối try:
try (BufferedWriter bw = new BufferedWriter(
        new FileWriter("sinhvien.txt", true))) {
    bw.write("Nguyễn Văn An, GPA: 9.0");
    bw.newLine();
} catch (IOException e) {
    e.printStackTrace();
}
Chế Độ Ghi Đè vs Ghi Nối Tiếp
new FileWriter("f.txt")

Chế độ ghi đè (Overwrite): Xóa sạch nội dung cũ của file và viết lại từ đầu.

new FileWriter("f.txt", true)

Chế độ ghi nối (Append): Giữ nguyên nội dung cũ, chèn thêm dòng mới vào cuối file.

Mục 9.4

Áp Dụng Luồng Cho Kết Nối Mạng (Socket)

Sức mạnh tuyệt vời của cơ chế I/O trong Java: File hay Kết nối mạng Internet đều thao tác y hệt nhau! Chỉ cần lấy được InputStream hoặc OutputStream từ Socket là đọc ghi tương tự một file trên ổ cứng. 

// Kết nối tới server qua Socket TCP:
Socket socket = new Socket("api.example.com", 80);

// Lấy luồng đọc từ mạng y chang đọc file:
BufferedReader reader = new BufferedReader(
    new InputStreamReader(socket.getInputStream()));

String message = reader.readLine(); // Đọc gói tin gửi từ server!

Mục 10.1

Bộ Nguyên Tắc Thiết Kế S.O.L.I.D

SOLID là 5 nguyên tắc vàng do Robert C. Martin (Uncle Bob) đúc kết, giúp kiến trúc phần mềm chống lại hiện tượng "mã nguồn bốc mùi" (code smell), dễ bảo trì và dễ mở rộng khi dự án lên hàng triệu dòng code.

  • S - Single Responsibility: Đơn trách nhiệm.
  • O - Open/Closed: Mở rộng tính năng, đóng việc sửa mã cũ.
  • L - Liskov Substitution: Lớp con thay thế hoàn hảo cho lớp cha.
  • I - Interface Segregation: Chia nhỏ giao diện thành nhiều interface con.
  • D - Dependency Inversion: Phụ thuộc vào trừu tượng, không phụ thuộc cụ thể.
S: Đơn trách nhiệm 1 Class chỉ nên có 1 lý do duy nhất để thay đổi
O: Mở / Đóng Thêm tính năng bằng cách kế thừa, không sửa file cũ
L: Thay thế Liskov Lớp con không được làm sai lệch bản chất của lớp cha
I: Phân tách Interface Không ép lớp con thực thi hàm nó không dùng đến
D: Đảo ngược phụ thuộc Mô-đun cấp cao giao tiếp qua Interface, không gán cứng
Mục 10.1 Chi Tiết

Nguyên Tắc S & O Trong SOLID

  • Single Responsibility Principle (SRP): Một lớp chỉ làm đúng một chức năng. Tránh tạo lớp "God Object" vừa tính toán hóa đơn, vừa gửi email, vừa in PDF.
  • Open / Closed Principle (OCP): Mở cho việc mở rộng (thêm chức năng mới bằng cách tạo thêm lớp mới kế thừa/implements), nhưng Đóng đối với việc sửa đổi mã nguồn đã chạy ổn định.
Minh Họa OCP: Thanh Toán Mở Rộng
// Giao diện chung đóng không sửa:
interface ThanhToan { void pay(double amt); }
// Muốn thêm thanh toán Momo hoặc ZaloPay?
class MomoPayment implements ThanhToan { ... }
class ZaloPayPayment implements ThanhToan { ... }
➔ Thêm vô số cổng thanh toán mà không sửa 1 dòng code cũ!
Mục 10.1 Chi Tiết

Nguyên Tắc L, I & D Trong SOLID

  • Liskov (LSP): Lớp con phải thay thế được lớp cha mà không làm hỏng tính đúng đắn (Ví dụ: Chim Cánh Cụt kế thừa từ Chim nhưng không biết bay ➔ Vi phạm LSP).
  • Interface Segregation (ISP): Tách interface khổng lồ thành nhiều interface chuyên biệt, tránh ép lớp con viết hàm rỗng.
  • Dependency Inversion (DIP): Các module cấp cao (OrderService) không gọi trực tiếp module cấp thấp (MySQLDatabase), mà cả hai phụ thuộc vào Interface trừu tượng (DatabaseRepository).

Mục 10.2

Khái Niệm Mẫu Thiết Kế (Design Patterns)

Design Pattern là giải pháp tổng quát đã được kiểm nghiệm thực tế để giải quyết các vấn đề thường xuyên lặp đi lặp lại trong quá trình thiết kế phần mềm hướng đối tượng.

Creational Mẫu khởi tạo (Singleton, Factory, Prototype)
Structural Mẫu cấu trúc (Adapter, Decorator, Facade)
Behavioral Mẫu hành vi (Observer, Strategy, Template)
Lợi Ích Khi Áp Dụng Mẫu Thiết Kế
Tránh việc "phát minh lại bánh xe" (Reinventing the wheel).
Tạo tiếng nói chung chuyên nghiệp giữa các lập trình viên trên toàn cầu.
Đảm bảo kiến trúc đạt chuẩn OOP và các nguyên lý SOLID tối đa.
Mục 10.2 - Mẫu Điển Hình 1

Mẫu Singleton (Đơn Thể Duy Nhất)

• Mục đích: Đảm bảo chỉ có DUY NHẤT một thể hiện (instance) của lớp tồn tại trong toàn bộ vòng đời chương trình (Ví dụ: Kết nối Database, Trình ghi Log hệ thống).
• Cài đặt: Khóa constructor bằng private và cung cấp hàm tĩnh getInstance(). 

public class DatabaseConnection {
    private static DatabaseConnection instance;

    // 1. Khóa constructor: Cấm bên ngoài gọi new!
    private DatabaseConnection() { }

    // 2. Điểm truy cập toàn cục duy nhất
    public static DatabaseConnection getInstance() {
        if (instance == null) instance = new DatabaseConnection();
        return instance;
    }
}

Module OrderService ➔ dùng chung

Mục 10.2 - Mẫu Điển Hình 2

Mẫu Factory Method (Nhà Máy Tạo Đối Tượng)

• Mục đích: Ủy thác việc tạo đối tượng cho một "nhà máy" (Factory) thay vì gọi trực tiếp lệnh new rải rác trong code. Giúp tách rời (decouple) mã giao diện khỏi các lớp cụ thể. 

public class ThongBaoFactory {
    public static Notification taoThongBao(String kieu) {
        if (kieu.equals("SMS")) return new SMSNotification();
        if (kieu.equals("EMAIL")) return new EmailNotification();
        return null;
    }
}
// Sử dụng đơn giản:
Notification notif = ThongBaoFactory.taoThongBao("SMS");

Factory (Nhà Máy Sản Xuất)

↓ Sản xuất đối tượng theo yêu cầu ↓
SMSNotification
EmailNotification
Mục 10.2 - Mẫu Điển Hình 3

Mẫu Observer (Người Quan Sát / Đăng Ký Nhận Tin)

• Mục đích: Định nghĩa mối quan hệ 1-Nhiều (1-to-Many). Khi một đối tượng (Subject) thay đổi trạng thái, toàn bộ các đối tượng phụ thuộc (Observers) đã đăng ký theo dõi sẽ tự động nhận được thông báo cập nhật ngay tức khắc. 

// Kênh Youtube (Subject) phát video mới:
public void dangVideoMoi(String tenVideo) {
    for (Subscriber s : danhSachDangKy) {
        s.nhanThongBao(tenVideo); // Broadcast tới mọi subscriber!
    }
}
